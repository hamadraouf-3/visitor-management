# Phase 1 — Frontend foundation: decisions and deviations

Date: 2026-10-05 · Scope: `frontend/` · Contract: `docs/initial-assessment.md` revision 2

Each entry: **decision** — reason. Items marked *(gate)* need confirmation or a matching choice on the backend side.

## Dependencies (§3.2-10: all frontend dependencies are installed now)

1. **Added `lucide-react` (ISC) for icons.** — Status badges, navigation, alerts and later screens (scanner, reception) need a consistent icon set; hand-drawing ~40 icons is error-prone. Icons are inline SVG (CSP-safe) and tree-shaken.
2. **Added `@axe-core/playwright`** (Phase 9 accessibility assertions), **`@vitest/coverage-v8`** (`npm run test:coverage`) and **`@testing-library/dom`** (required peer of `@testing-library/react` 16). — So later phases need no dependency changes.
3. **`barcode-detector` pinned to exactly `3.2.2` and `zxing-wasm` to exactly `3.1.3`.** — barcode-detector bundles the zxing JS glue for zxing-wasm 3.1.3; the `.wasm` we self-host (imported from `zxing-wasm` via `?url`) must be that exact build. `src/scanner/zxingWasm.test.ts` asserts the version and the SHA-256 (`ZXING_WASM_SHA256`). Upgrade both together.
4. **No chart, form, date-picker or HTTP-client libraries.** — Reports can use simple in-house SVG/CSS bars; forms use controlled inputs + pure validators; dates use the native `datetime-local` input wrapped by `DateTimeField`. A later need for a dependency must be recorded per §3.2-10.

## Tooling

5. **TypeScript ~6.0 (6.0.3) with `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`.** — Stricter than the template; catches index/undefined bugs early.
6. **oxlint with `react`, `typescript`, `oxc`, `unicorn`, `import`, `jsx-a11y`, `vitest`; categories correctness=error, suspicious=warn; `npm run lint` uses `--deny-warnings`.** Two rules are off: `react/react-in-jsx-scope` (automatic JSX runtime) and `jsx-a11y/prefer-tag-over-role` — the UI kit deliberately implements WAI-ARIA APG widgets (modal dialog, listbox/option combobox, status regions, `svg role="img"`) instead of native `<dialog>`/`<select>`/`<output>`, which cannot meet the focus-management, styling and async-option requirements. All other jsx-a11y rules stay on.
7. **`VMS_API_PROXY_TARGET` env var** (not `VITE_`-prefixed, so never exposed to client code) overrides the dev/preview proxy target (default `http://localhost:8000`). — §2 requires automated runs (Phase 9 E2E) to use their own ports.
8. **`vite preview` runs on 4173 with `strictPort` and proxies `/api` too**, so a production build can be exercised against a backend with the real security headers.
9. **`npm run e2e` = `playwright test --pass-with-no-tests`.** — Placeholder until Phase 9 adds specs and global setup; `playwright.config.ts` already defines the three §11 viewports (1440×900, 820×1180, 390×844). Phase 9 should drop the flag. No browsers were downloaded.
10. **Vitest runs with `TZ=UTC`**; timezone tests additionally switch the process timezone at runtime (Auckland, Los Angeles, Tokyo) to prove independence from the browser timezone.

## Security headers / PWA

11. **Preview sends the §10 header set plus `X-Frame-Options: DENY` and `Cross-Origin-Opener-Policy: same-origin`** (defined once in `frontend/config/securityHeaders.ts`). — Defence in depth for older browsers; harmless for this app. The production nginx config should use the same list *(gate: Phase 9 nginx)*.
12. **Service worker precache list is generated at build time** by a small Vite plugin (`config/serviceWorkerPrecache.ts`) that emits `sw-precache-manifest.js` (`self.VMS_PRECACHE_MANIFEST = {version, urls}`) — every emitted chunk/asset including the zxing `.wasm`, all public files and `/index.html`; `version` is a content hash. `public/sw.js` stays a static, readable file that `importScripts` the manifest. Registration only in production builds, with `updateViaCache: 'none'`. *(gate: nginx must serve `sw.js` and `sw-precache-manifest.js` with `Cache-Control: no-cache`, `.wasm` as `application/wasm`, and SPA fallback to `index.html`.)*
13. **`/reception` is a lazy route that preloads the QR decoder on mount** (§10 "Preload the decoder when /reception mounts"). — Done now so the self-hosted wasm is part of the build and the precache list, and the CSP (`'wasm-unsafe-eval'`) can be verified end to end. Phase 5 replaces the placeholder content and keeps the preload hook (`src/scanner/useQrDecoderPreload.ts`). Scanner code stays out of the main bundle.
14. **PWA icons are generated reproducibly** by `npm run icons` (`scripts/generate-icons.mjs`, Node built-ins only): 192/512 "any", 512 maskable (glyph inside the safe zone), 180 Apple touch icon; SVG icon + favicon share the geometry.
15. **Light theme only** (`color-scheme: light`). — Not required by the contract; avoids doubling the contrast verification surface.

## Auth & routing behavior

16. **Reset token is captured and stripped in the `/reset-password` route loader** (`history.replaceState(history.state, '', path)`), i.e. before the page component renders; the route never revalidates. — Satisfies §7.2 "strips the fragment before rendering" without side effects in render.
17. **Global 401 handling applies only when a session existed** (`['auth','me']` held a user): then `queryClient.clear()`, `me := null`, redirect to `/login?next=<page>`. An anonymous 401 is the normal signed-out state. 403 `PASSWORD_CHANGE_REQUIRED` marks `me.user.must_change_password` and goes to `/change-password`.
18. **Sign-out:** a 401 from `POST /auth/logout` counts as success (session already gone); any other failure (e.g. offline) keeps the user signed in and shows an error toast, so a shared tablet is never shown as signed out while the server session lives. **Sign-in** removes all cached queries before storing the new `Me`.
19. **`next` handling:** only same-origin relative paths; protocol-relative, absolute, backslash and control-character values are rejected; fragments are dropped (may carry tokens); auth pages and `/pass` are never destinations. *(Corrected in 39: the checks now also apply to the normalised path.)*
20. **`RequireRole` redirects to the user's own landing page** (role priority §10) rather than showing a 403 page; an "access denied" state is shown only if that would loop.
21. **Route access:** `/visits/:id` and `/visitors`, `/visitors/:id` are open to every role (reads are scoped server-side; reception/management/history need visit details); `/visits` and `/visits/new` to EMPLOYEE + SYSTEM_ADMIN; `/reception` to RECEPTIONIST + SYSTEM_ADMIN; `/history` and `/inside` to SYSTEM_ADMIN + MANAGEMENT + RECEPTIONIST; `/reports` to MANAGEMENT + SYSTEM_ADMIN; `/admin/*` to SYSTEM_ADMIN. Defined once in `src/auth/roles.ts` (`SECTION_ACCESS`).
22. **`/change-password` renders inside the app layout; while a change is required the navigation is hidden** (every other endpoint answers 403 until then). The catch-all **404 page is public** (a mistyped link never forces a sign-in).
23. **Navigation labels:** "Inside now" (`/inside`), "Visit history" (`/history`); sections "Insights" and "Administration".
24. **Forgot-password confirmation is one fixed text for every address** (the typed address is not echoed). Network/5xx failures are reported because they never reached the account check (no oracle). *(Updated in 47: the text is now the server's message, which is identical for every address.)*

## API contract mirror (`src/types/api.ts`)

25. Section 1 mirrors §8.1 verbatim (the `WalkInCreate.reason` union is also exported as `WalkInReason`; structurally identical). Section 2 adds `ApiErrorEnvelope`, `Paginated<T>` and the `ApiErrorCode` union (§8.2 plus the backend's B1-08 codes `BAD_REQUEST` and `METHOD_NOT_ALLOWED`, see 34). Section 3 types the request bodies/query parameters from the §8 table (frontend-only names); `UserListParams.role` accepts one role or an array, sent comma-separated (B1-20). *(Superseded in 49: `role` is `Role[]`, and `ApiErrorEnvelope.error.code` is a plain `string`.)*
26. *(gate)* **Update bodies accept `null` to clear optional fields**: `UserUpdate.phone/department_id`, `VisitorUpdate.email/phone/company_name`, `VisitUpdate.department_id`. The backend should accept `null` (and, per §4, may also accept `''` normalised to NULL).
27. **Client-only error codes** on `ApiError`: `NETWORK_ERROR` (status 0, friendly message) and `UNEXPECTED_RESPONSE` (non-envelope error or non-JSON 2xx, e.g. a gateway page). The client reads `X-Request-ID` as a fallback for `requestId`.
28. **Query retries:** only network errors, 502/503/504 and `SERVICE_BUSY`, at most twice; 4xx/500 are never retried; mutations never retry.

## UI details

29. **Dates/times use fixed, locale-independent formats**: `EEE, d MMM yyyy`, 24-hour `HH:mm`, ranges with an en dash; durations `1h 37m` / `45m` / `< 1m` (hours are not rolled into days). **Wall-time DST policy:** a time inside a spring-forward gap moves forward (NY 02:30 → 03:30 EDT, and `DateTimeField` explains it); an ambiguous fall-back time resolves to its first occurrence. "Next half hour" is computed on the instant timeline so it is correct inside an overlap.
30. **QR codes render as inline SVG built from `qrcode.create()`'s module matrix** (no canvas/data URL): CSP-safe, crisp when printed, testable. A unit test decodes the rendered matrix with the self-hosted zxing wasm and checks it round-trips to the pass URL. The pass page encodes `${location.origin}/pass#<token>` (same payload shape as the email QR).
31. **Form-control borders use slate-500 (4.77:1)** to meet WCAG 1.4.11 (3:1 for UI boundaries); all text/background token pairs were computed ≥ 4.5:1 (noted next to each token in `src/index.css`).
32. **Toasts keep both live regions mounted at all times** (polite for confirmations, assertive for errors; error toasts do not auto-dismiss). Tests therefore look up alerts by text (`findAlert`) rather than `getByRole('alert')`.

## Gate review round 1 (2026-10-05)

33. **Pass-token parsing is an explicit grammar shared with the backend through one vector table.** — §6 requires the same pure parser on both sides. Rule: trim; a bare token is `[A-Za-z0-9_-]{32,128}`; otherwise a pass URL without spaces or ASCII control characters that fully matches `[Hh][Tt][Tt][Pp][Ss]?://[^/?#@\\]+/pass/?(\?[^#]*)?#<token>` (http/https only, any host and port, no user info, path exactly `/pass` or `/pass/`, case-sensitive). The frontend no longer uses WHATWG `URL` parsing, which normalises dot segments, backslashes and embedded tabs that a Python parser would not, so the sides could disagree. The 46 cases live in `frontend/src/scanner/pass-token-vectors.json` (rules stated in the file); Vitest runs every case. The file sits in `frontend/` only because this fixer may not write elsewhere; moving it to `docs/contract/pass-token-vectors.json` is fine (one import path changes). *(gate: backend)* `extract_pass_token` must run the same table; today it disagrees on 10 cases (accepts scheme-less, protocol-relative and path-only input, a path prefix such as `/vms/pass`, dot/double-slash paths, `https:/host`, user info, and embedded spaces/tabs). `APP_BASE_URL`/`QR_BASE_URL` must be restricted to an origin without a path (the SPA serves `/pass` and `/reset-password` at the root). *(Updated in 43: the vectors now live in `docs/contract/`.)*
34. **`api.ts` is checked automatically against the backend's Pydantic schemas** (§3.2-9). — `src/types/api.contract.test.ts` compares every exported type with `src/types/backend-contract.json` (23 response models, 19 request bodies incl. the check-in/check-out discriminated unions, and the full error-code list) using the TypeScript compiler API (`src/test/contractParity.ts`, which has its own tests for each kind of drift). Rules: responses must match exactly (properties, optionality, nullability, enum values, arrays, nested objects); an optional response property is *omitted*, never `null` (as `User.cancelled_visits` with `exclude_if`), so its nullability is not compared; requests must match properties and optionality, and may be stricter than the backend about `null` but never looser. The snapshot is regenerated with `npm run contract:snapshot`, which runs `frontend/scripts/dump-backend-contract.py` with the backend's virtualenv (backend code is only imported; no bytecode is written). *(gate: backend)* This dump belongs in the backend together with a pytest that fails when the checked-in snapshot is stale; until then a backend schema change is only caught after someone regenerates the snapshot. Keep the output format (`responses`/`requests` keyed by the TypeScript name, shared `$defs`, `error_codes`) so the frontend test stays unchanged. *(gate: Phase 5)* `ScanErrorDetails` must be serialised without `null` members (`exclude_none`), matching the optional TS fields. *(Updated in 42: the dump is now backend-owned. Extended in 49: query parameters and envelopes are compared too.)*
35. **`Table` keeps table semantics in the stacked small-screen layout.** — WebKit drops implicit table roles once `display` changes to block/flex, and `display: none` on the header row removed the column headers from the accessibility tree. The table now carries explicit `table`/`rowgroup`/`row`/`columnheader`/`cell` roles (the two jsx-a11y rules that flag redundant roles are disabled for that block only, with the reason), the header row is visually hidden below `md` instead of removed, and the small-screen labels are real text marked `aria-hidden` (the column header already names each cell) instead of CSS generated content.
36. **Auth screens follow the thin-page rule (§3.1).** — Pages only set the document title and compose layout + one feature component; the forms and their states live in `features/auth/{Login,ForgotPassword,ResetPassword,ChangePassword}Form.tsx`; all auth mutations are hooks in `src/auth/useSessionActions.ts` (`useRequestPasswordReset`, `useResetPassword` ends the local session after a reset). Route literals in `roles.ts` and `useSignOut` were replaced with `paths`. This is the pattern for later features.
37. **UI kit additions for §10 screens: `RadioGroup`, `DateField`, `CopyButton`.** — `RadioGroup` uses native radios in a `fieldset role="radiogroup"` (browser arrow-key behaviour; the role adds `aria-required`/`aria-invalid`), with `list` and touch-sized `segmented` variants (walk-in reason quick-pick, scan `check_in_options`); the selected segment shows a check mark, not color alone. `DateField` wraps the native date input for company-local `YYYY-MM-DD` filters through `Field` (no timezone conversion; optional hint naming the company timezone); `isDateKey` validates real calendar dates. `CopyButton` (+ `utils/clipboard.ts`) uses the async Clipboard API, falls back to `execCommand('copy')` — deprecated, but the only option on plain-http LAN origins where `navigator.clipboard` does not exist — and otherwise tells the user to copy manually; results are announced in a live region mounted from the first render. The button is not disabled while copying, because disabling a focused button drops keyboard focus. *(Generalised in 45 to every kit button.)*

## Gate review round 2 (2026-10-05)

38. **The combobox only navigates options the user can see.** — `AsyncCombobox` keeps the previous search's matches in `options` while a new search loads (`keepPreviousData`, no flicker), but the listbox is hidden then. Before this change, arrows moved through those hidden options, `aria-activedescendant` pointed into the hidden listbox, and Enter selected one, so a fast typist could pick a host or visitor they never saw. `Combobox` now derives `navigable = open && !loading && !errorMessage && !idleMessage && options.length > 0`. Arrows and Enter do nothing, and there is no active descendant, unless the list is navigable. The active option is cleared whenever the navigable list changes, compared by option keys so a re-render with an equal list keeps the user's place. **Also, Enter never submits the surrounding form while the popup is open**: the typed text is not a selection yet, and submitting would send the previous selection (e.g. the default host) while the field shows other text. Escape or Tab closes the popup first. Tests cover the loading, error and idle states, a list change, and the real `AsyncCombobox` race (ArrowDown+Enter before new results arrive selects nothing).
39. **`safeNextPath` validates the normalised path it returns.** — The `//` check ran on the raw input, but dot segments normalise into a protocol-relative path (`/.//evil.com`, `/%2e//evil.com`, `/%2E%2E//evil.com`, `/x/..//evil.com` → `//evil.com`). React Router 8.4 then threw "External navigation is not allowed" during render, and the user saw the error page after signing in. Both the input and the normalised `url.pathname` must now be root-relative: they start with `/`, not with `//`, and contain no backslash. A login-page test covers the end-to-end case, and a property test checks that every accepted result passes re-validation unchanged.
40. **Vite's CORS middleware is off for `dev` and `preview` (`cors: false`).** — §3 says "no CORS anywhere". Vite's default answered any localhost origin and preflights on the proxied `/api`. `config/viteConfig.test.ts` (Node environment) checks the values Vite gates on (`resolveConfig(...).server.cors` and `.preview.cors` are exactly `false`) and the raw config in every mode, including `https`. Vitest's `include` now also covers `config/**/*.test.ts`.
41. **Test hygiene: unhandled API calls fail the test, and the QR decoder is inert in tests.** — `mockApi` records every request that has no route, in addition to rejecting it, because the API client turns the rejection into a `NETWORK_ERROR` that the UI may swallow. `src/test/setup.ts` calls `assertNoUnhandledRequests()` after every test, so the test fails and names each `METHOD /path`. The setup also replaces `src/scanner/zxing.ts`, the only module that downloads or compiles the wasm, with a fake typed against the real module's signatures: no native detector, the preload resolves `'zxing'`, detections find nothing. Without it, any test that rendered `/reception` started a real wasm fetch in jsdom. `zxing.test.ts` opts out with `vi.unmock('./zxing')`, and the per-file mock in `guards.test.tsx` was removed. Also corrected the `scanPass` doc comment: READY and ALREADY_CHECKED_IN resolve (200), while §6 rows 1–3 and 5–8 reject with `ScanErrorDetails`.

## Gate review round 3 (2026-10-05)

45. **A button never disables itself while it has focus.** — `Button` set the native `disabled` attribute while `loading`. Every submit button therefore became disabled while focused, and `Pagination` did the same when Next reached the last page (or Previous the first). Browsers then move focus to the document (the HTML focus fixup rule), so keyboard and screen-reader users had to start again from the top after every submit or page change. This also defeated the §10 reception rule "after a result, focus moves to the primary action; after the action, back to the input". Now `loading` renders `aria-disabled="true"` and `aria-busy="true"`, keeps the button focusable, and makes activation a no-op. The click handler calls `preventDefault`, which also cancels form submission, including implicit submission by Enter in a text field. A new `focusableWhenDisabled` prop gives `disabled` the same treatment for buttons that can become unavailable while focused; `Pagination` uses it. The native attribute stays for buttons that are unavailable before anyone can focus them. `Button` owns `aria-disabled` and `aria-busy`; they were removed from its props. **jsdom does not apply the focus fixup rule** (a focused element that becomes disabled stays focused), so no focus assertion could catch this bug. `src/test/setup.ts` now emulates the rule: a `MutationObserver` on `disabled` moves focus to the body, because jsdom's `blur()` ignores an element that is no longer focusable. The emulation has its own tests in `src/test/focusFixup.test.ts`. With the old `Button`, 11 tests now fail, including the sign-in, change-password, reset-password and forgot-password page tests. The Pagination tests moved from `Table.test.tsx` to `Pagination.test.tsx`.
46. **Shared form-error handling: `src/utils/forms.ts` and `src/hooks/useFormErrors.ts`.** — `FormErrors` and `hasErrors` moved out of `features/auth/validation.ts`, which now holds only the auth validators. `useFormErrors(mutation.error, { fields, codes })` replaces the pattern each auth form had copied by hand, and is the pattern for the forms of Phases 2–7:
    - `fields` lists every form field with the server path(s) that report it, e.g. `{ visitorEmail: 'visitor.email' }`, or `[]` for client-only fields such as a confirmation. `codes` maps error codes that describe one field, e.g. `INVALID_CURRENT_PASSWORD → currentPassword`.
    - Per field, the client message wins over the server message, because it describes the current input.
    - `formError` holds what only the form alert can show. That is the error message when no field is concerned, or the server field messages whose path the form does not show, such as `body` (model-level rules, malformed JSON) or the hidden reset `token`. Such messages are never dropped. It is null when the fields show everything.
    - After a failed submit (client validation fails, or a new server error has field messages), focus moves to the first invalid control in document order. This happens after the render that shows the message, so the control is announced together with its error. A radio group receives focus through its checked radio, or its first one. Errors that concern no field leave focus where it is: on the submit button, which now keeps focus (45). The `role="alert"` alert announces them.
    - `form.field(name)` returns `{ id, error }` to spread on `Field`, `DateField`, `DateTimeField` or `RadioGroup`.
    All four auth forms use the hook.
47. **The forgot-password confirmation is the server's `ForgotPasswordResponse.message`.** — The form hard-coded its own text, including "The link expires in 30 minutes", which duplicated the backend's `PASSWORD_RESET_TTL` and would drift when that changes. The server's message is identical for every address (§7.2), so showing it creates no oracle, and the typed address is still never echoed. Only a 202 without a message (e.g. a proxy that dropped the body) falls back to a fixed sentence, which states no lifetime.
48. **Source encoding is checked by a test.** — `parsePassToken.ts` and `parsePassToken.test.ts` still began with a UTF-8 BOM (contrary to 44). The test also held four raw invisible characters inside template literals (U+FEFF, U+00A0, U+3000, U+2028), which are exactly the characters this module's grammar trims. Both files are now UTF-8 without a BOM, and those characters are written as `\uXXXX` escapes. `config/sourceEncoding.test.ts` (Node) fails on a BOM, on invalid UTF-8, or on any raw control character, format character (including zero-width and bidirectional "Trojan Source" controls), or space or line separator other than U+0020. It checks every text file in `frontend/` (except the ignored dependency, build and report folders) and, read-only, `docs/contract/pass-token-vectors.json`, which the frontend imports. While I was writing the check, the agents' file-writing tool turned `\u` escapes in the new file into raw characters, and the check caught them; this is probably how the test file got them. After writing such characters, run the check.

## Gate review round 3, verification follow-up (2026-10-05)

49. **Query parameters and envelopes are compared with the backend too (§3.2-9).** — The snapshot has carried `queries` (the eight `*Params` models) and `envelopes` (`ApiErrorEnvelope` and the `Paginated<T>` of every paginated endpoint) since the backend took over the dump, but `api.contract.test.ts` read only `responses`, `requests` and `error_codes`. Running the comparator on the two unread sections reported six mismatches, and a renamed or retyped filter (`status`, `order`, `scope`, `date_from`) would also have passed. Now:
    - `queries` are compared in request mode and `envelopes` in response mode, like the bodies.
    - Two guards keep the test complete. The first fails when the snapshot gains a top-level section the test does not compare. The second fails when `api.ts` exports a type that is neither in the snapshot nor in a short list of building blocks checked another way: the enum aliases, `Paginated`, `ApiErrorCode` and `ValidationErrorDetails`.
    - **`UserListParams.role` is `Role[]`** (supersedes 25's "one role or an array"). The backend's `UserListQuery.role` is `list[Role]`. A single role is `['MANAGEMENT']`. The wire format is unchanged: comma-separated.
    - **`ApiErrorEnvelope.error.code` is a plain `string`**, the wire type of the backend's `ErrorBody.code`. Callers still narrow through `ApiError['code']` (`ApiErrorCode | ClientErrorCode | (string & {})`) in `api/client.ts`. The comparator reads the open-ended union as a different type from `string`, and the envelope only describes what arrives.
    - **Named page types `UserPage`, `VisitorSearchPage`, `VisitPage` and `AuditLogPage`** (`Paginated<…>` aliases) are the return types of `listUsers`, `searchVisitors`, `listVisits`, `listVisitorVisits` and `listAuditLogs`. Each paginated response is compared through the name the backend publishes.
    - The comparator's own tests now cover a named instantiation of a generic interface (match and nested item drift), a filter that also accepts a scalar where the backend takes a list, and an open-ended literal union where the backend has a plain string.
    - Mutation check: renaming `VisitListParams.order` and making `status` a scalar both fail the query test.

    For Phases 2–7: a new paginated endpoint gets a `*Page` alias in `api.ts` and an `ENVELOPES` entry in `backend/app/contract.py`. A new query model gets a `*Params` type and a `QUERIES` entry.

    The curated round-3 frontend items F1–F7 were re-verified against the code and need no further change: the combobox is covered by 38, `safeNextPath` by 39, Vite CORS by 40, test hygiene and the `scanPass` comment by 41, the snapshot script by 42 (`npm run contract:snapshot` rewrites the committed file byte for byte) and the vectors import by 43 (`tsc -b` passes).
