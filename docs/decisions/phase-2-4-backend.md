# Phases 2–4 — backend decisions

Date: 2026-10-05. Scope: `backend/` (visitors, visits, passes and scan validation, e-mail), plus the
Phase 1 carry-over items. Each entry records a deviation from, or an interpretation of,
`docs/initial-assessment.md` (revision 2), with the reason. The §8.1 schemas are unchanged; the only
contract change is one new error code (B24-02).

| B24-01 | **Response-model failures are 500 `INTERNAL_ERROR` without personal data in the logs.** `register_exception_handlers` handles FastAPI's `ResponseValidationError` and Pydantic's `ValidationError` (raised while a service or route builds a response model; request bodies and queries arrive as `RequestValidationError`). | B24-02 | **Request bodies are capped: 413 `PAYLOAD_TOO_LARGE` "The request is too large."** (new code, added to the §8.2 catalogue here). `BodySizeLimitMiddleware` (pure ASGI) sits inside `RequestContextMiddleware` (the envelope carries the request ID and API headers) and outside the CSRF middleware. For API paths it refuses a declared `Content-Length` above `MAX_REQUEST_BODY_BYTES` (new setting, default 65,536, range 1 KiB–10 MiB) without reading the body; without a declared length, or with a wrong one, it counts bytes as the application reads them and, past the limit, raises into the application, discards whatever it answers and sends the 413. Every contract body is far below 64 KiB. |
