## Visit history (`/history`, D-25)

6. **Filters, all in the URL** (`?from=&to=&status=&host=&hostName=&department=&q=&page=`; `historyFilters.ts`, unit-tested): scheduled-date range (company-local, B24-21), status multi-select, host, department, and free text (`q` matches visitor, visitor company and host names on the server). Requests are `scope=all&order=desc&page_size=25`. Malformed values in a hand-edited link (impossible dates, non-UUID IDs, unknown statuses) are ignored instead of sent. Any filter change returns to page 1. An end date before the start date shows the error on the "To" field and makes **no request** (the server would answer 422).
7. **Host filter = `GET /users/hosts` (active hosts only), with the name kept in the URL (`hostName`).** — Management and reception cannot read `GET /users`, and the host directory has no lookup by ID, so a shared link shows the name without another request. A deactivated host's visits are found through the text search (it matches the host-name snapshot); the hint says so. *(gate: backend, optional)* A host search that includes former hosts would let the picker offer them.
8. **Department filter as a combobox that loads the list when first opened** (or when a department is already selected), filtered as the user types. Administrators get `include_inactive=true` (others would get 403, B1-19), marked "Inactive". A department ID the caller cannot list shows as "Department not listed".
9. **Rows** link to the visit page with a back link to the exact view. Method badges: Override, Walk-in, Corrected check-out, Bulk check-out (icon and text), explained in a legend under the table for the badges on the current page (the tooltip alone would leave touch and keyboard users out). Below `lg` the card shows check-in, check-out and duration as one "Attendance" line (`formatAttendance`); the three separate columns are table-only. Filters collapse behind "Filters (n)" on phones. *(Amended in [phase-5-7-frontend-round2.md](phase-5-7-frontend-round2.md) FY-7.)*

## Inside now (`/inside`, evacuation list)

10. **Roll-call order: by visitor name** (accent- and case-insensitive collation), then host, then ID, so rows never swap between refreshes. The server's `count` is the headcount; overdue and earlier-day flags are counted over the rows and shown as tiles and per-row badges (warning tone, icon and text). *(Amended in [phase-5-7-frontend.md](phase-5-7-frontend.md) FX-7.)*
11. **Refresh every 15 s; `X-Background-Refresh: 1` only on automatic refreshes.** — The interval and focus refetches send the header (§7.2: polling must not keep an idle session alive); the first load and the "Refresh" button (a person acted) do not. `staleTime: 0`, so returning to the tab refetches. If a refresh fails, the last list stays with a warning that names its time. *(Amended in [phase-5-7-frontend.md](phase-5-7-frontend.md) FX-4.)*
12. **"Generated at" = the moment the data arrived** (`dataUpdatedAt`, shown to the second in the company time zone). — §8.1 `InsideList` has no server timestamp. *(gate: contract owner, optional)* A server `generated_at` would make the printout independent of the client clock.
13. **Print = a print-only copy of the list in the page**, `hidden print:block`, `aria-hidden`; the screen content is `print:hidden` and the app shell already hides its sidebar and top bar in print. Black on white: company, "Evacuation list: visitors on site", generated date and time with the time zone, headcount, then #, visitor, company, host, host phone, department, check-in, notes and an empty "Present" box for the roll call, and "Printed by". Done with Tailwind print variants only: `index.css` is not mine, and the CSP (`style-src 'self'`) forbids an inline `<style>`. `lg:print:-ml-64` cancels the layout's sidebar padding on wide paper. **"Print list" first fetches the current list**, waits until it is rendered, then calls `window.print()`; if the fetch fails it prints the last list and says from when. Checked as A4 PDF in Chrome: one page, all columns fit. *(Amended in [phase-5-7-frontend.md](phase-5-7-frontend.md) FX-28.)* *(Amended in [phase-5-7-frontend-round2.md](phase-5-7-frontend-round2.md) FY-12.)*
14. *(gate: reception builder)* The page shares `queryKeys.reception.inside` with the reception screen's Inside tab; both read the same `InsideList`. *(Amended in [phase-5-7-frontend.md](phase-5-7-frontend.md) FX-4.)*

## Administration

15. **Admin dashboard tiles open exactly the set they count** (the Phase 2–4 lesson of finding 1): "Visits today" → the history for today without cancelled visits (the server excludes them); role tiles → active users with that role (`count_active_by_role`). Counts use grouped thousands. The latest ten audit events use the audit labels and links (19).
16. **Users.**
    - List: search (name or email), role, status (`all`/`active`/`inactive`), all in the URL; badges for roles, "Inactive" and "Temporary password" (`must_change_password`); last sign-in relative to the company day.
    - **Create**: full name, email, phone, department (active ones), roles (checkboxes with what each role allows), temporary password with the browser-checkable policy shown live (12–128 code points, not the email address; "not a common password" is the server's, §7.1). **Generate** uses `crypto.getRandomValues` with rejection sampling (no modulo bias): four groups of five characters from a 56-character alphabet without 0/O/o/1/l/I, about 116 bits, easy to read aloud. After creation the dialog shows the password **once** with Copy and the 72-hour expiry (D-11); it lives only in component state and in a mutation with `gcTime: 0`.
    - **Edit**: name, phone, department (the current one is offered even if inactive), roles, active; only changed fields are sent, a cleared phone or department as `null`. The email is shown, not editable (`UserUpdate` has no email).
    - **Never offers self-demotion**: on one's own account the Administrator role and "Account is active" are disabled with the reason (§7.5).
    - **Errors**: `USER_EMAIL_UNAVAILABLE` on the email field; `LAST_ADMIN` on the roles group or on the active switch, whichever change caused it; `SELF_MODIFICATION` (only reachable through a stale page) in the form alert; 422 field messages on their fields.
    - **D-18**: a change that deactivates the user or removes their last host role shows a warning before saving ("every scheduled visit they host is cancelled; visitors who were sent an invitation are told by email", B24-70) and turns the button into a danger "Deactivate user" / "Save and cancel hosted visits". After saving, `cancelled_visits` is reported in a toast, and visit lists, reception and dashboards are refreshed. Reactivation explains that the old password or "Forgot password" works again.
17. **Departments.** One request with `include_inactive=true`; "Show inactive departments (n)" filters on the client and is kept in `?inactive=1`. Create and rename check the name against every department, case-insensitively and inactive ones included (§4 unique index), before sending ("An inactive department has this name. Reactivate it instead."); the server's 409 `CONFLICT` shows on the field too. Deactivation asks for confirmation; reactivation is immediate. When a deactivated department leaves the list, focus moves to the page heading instead of the document.
18. **Company settings.**
    - The PATCH contains only what changed **compared with the settings the form was opened with**, so a refetch never overwrites edits or another administrator's untouched fields; cleared address and email domain are `null`.
    - Time zone: searchable combobox over `Intl.supportedValuesOf('timeZone')` (fallback: 37 business-region zones), always including UTC and the current value, each with its current UTC offset; "new york" finds `America/New_York`. Options are only rendered while the popup is open. The server stays the authority (422 `timezone` shows on the field).
    - Email domain: the server's rule (`normalise_domain_name`, B1-54) mirrored; grace minutes: digits only, 0–1440, with "90 minutes (1 hour 30 min)" read-back.
    - Explanations: grace changes apply to visits created or rescheduled after saving; a time zone change moves how times are shown, never stored instants (D-15).
    - **Unsaved-changes guard**: `useBlocker` (in-app navigation, a "Leave without saving?" alert dialog) plus `beforeunload`. After saving, `me` is refetched so the shell shows the new name and time zone.
19. **Audit log.**
    - **Labels for all 44 actions in `backend/app/services/audit.py`** (grouped for the filter), and a fallback humaniser for any newer action. `auditLabels.test.ts` (Node environment) parses `AuditAction` and `AuditEntity` from the backend source and fails if an action lacks a label **or** if a label names an action the backend does not record. The concurrent backend builder added nine actions during this phase (check-in/out and their refusals, bulk check-out, walk-ins and their refusals, a refused visitor link, `USER_CHANGE_REFUSED`); the test caught the last one, the others were reconciled when the source was re-read.
    - Each event: time to the second, label, a qualifier from `outcome`/`reason`/`code`/`policy` ("Invalid", "Unknown account", "Override not allowed"), a warning mark for failures and denials (security events, refusals, unusable scans), the actor or "System or anonymous", and the entity: visits and visitors link to their pages, other entities to the audit log filtered by that entity (they have no page).
    - **Expandable rows**: a list of events with a disclosure button each (`aria-expanded`), not a table: an expandable row inside a table is awkward on phones and for screen readers. Details: exact time (company and UTC), sequence number, actor ID, entity, IP, request ID, user agent, the metadata as labelled values and as raw JSON. **Everything is rendered as text**; a test stores `<img onerror>` and `<script>` in metadata and checks no element is created.
    - Filters in the URL (`action`, `actor` + `actorName`, `entity_type`, `entity_id`, `from`, `to`, `page`; the entity keys match the API names so links read naturally). The actor filter searches `GET /users` (active and inactive accounts). An entity ID is only sent when it is a full UUID; otherwise the field says so on blur. Page size 50.

## Reports (`/reports`)

20. **The range is always sent** (`date_from`/`date_to`), default the last 30 days including today (company-local), so page and server agree on it; the default is kept out of the URL. Presets: last 7, 30, 90 days, this month, last month, last 12 months (365 or 366 days). A custom range applies only once both dates form a valid range of at most 366 days; until then the error is on the "To" field and the report keeps the last valid range. While a new range loads, the old report stays at reduced opacity (no spinner flash).
21. **Charts** (dataviz skill followed): one series per chart, so one color: the accent indigo-700 (`#432dd7`), validated with the skill's `validate_palette.js` against the white surface (all checks pass, contrast ≥ 3:1); the hovered or focused mark lifts to `accent-hover`. Thin columns (≤ 24 px, 4 px rounded data end, square foot, ≥ 2 px gap), hairline gridlines, round ticks, the peak labelled directly. Visits per day: columns up to 62 days, a 2 px line with a 10 % wash beyond. Departments: horizontal bars, largest first, the tail folded into "Other departments (n)" after eight, labels beside the bars (above them below 480 px). Check-ins by hour: 24 columns, 0–23, missing hours as 0. Top hosts: a table with each host's share. Every chart draws at its measured width (ResizeObserver) and scales down for print. *(Amended in [phase-5-7-frontend-round2.md](phase-5-7-frontend-round2.md) FY-9, FY-10.)*
22. **Accessibility**: each chart is a `figure` with a title and a one-sentence summary (busiest day or hour); every mark is a keyboard stop (one Tab stop per chart, arrows/Home/End) with "label: value" as its name; the data table is always in the accessibility tree (visually hidden in a wrapper, since a table ignores `sr-only`'s 1 px width and widened the page at 390 px) and "Show table" displays it. **Deviation from the skill's floating tooltip**: the value of the hovered or focused mark is shown in a fixed readout line above the plot (value first, then label). It never covers the marks and needs no positioning styles.
23. **Light theme only**, so no dark chart palette (Phase 1 decision 15).

## Known limits

- The backend for these endpoints was built at the same time; screens were verified against mocks typed by `api.ts`. I read the backend services afterwards and aligned the dashboard links (15) and report wording ("unique visitors" are people who came in person) with them.
- Audit pagination is by page over `seq` descending (the API's model): events arriving while someone pages shift the pages; "This page is empty" offers the first page.
- The history's host filter offers active hosts only (7).
